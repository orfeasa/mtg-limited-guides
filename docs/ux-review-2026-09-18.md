# Lifecycle UX review · 18 September 2026

Scope: shared shell, navigation/default routes, preview browsing, archetypes, Training, existing Draft decisions, source/progress states, responsive and keyboard behavior. Reviewed current live unrated Training and source contracts across both sets, then verified the resulting flows in the browser. This is an implementation-focused UX pass, not a scored independent design critique.

## Findings and decisions

1. **Training promised an exercise without answers.** FRA displayed “Card rating training”, Next card, missed-card instructions and 0/0 tier calls. This duplicates the browser and makes missing evidence look like a broken feature. Hide the entire mode until verified ratings exist; keep saved progress.
2. **The initial destination ignored readiness.** Every set defaulted to Training, including stale direct links. Use Previews while incomplete, Archetypes once the full map is ready, then Training once ratings are verified. Set switching follows the destination's default.
3. **Reveal, release and ratings were conflated.** The full 281-card file still claimed to be expanding; All cards appeared during previews; the same stage flag controlled both factual and rating copy. Persist actual evidence milestones separately from published dates. Rename the browser when the full card file is confirmed, independently of retail release and ratings.
4. **Provisional archetypes spent space on absent statistics.** “Not known”, “Pending” and redundant counts dominated the introduction. Remove that ledger until observations exist; retain a concise evidence explanation, official plans, format switch and signposts.
5. **Preview labels repeated without helping decisions.** Repeating Preview on all 281 rows adds scanning noise. State maturity once in the header and use rarity on unrated rows. Retire catch-up controls once the file is complete.
6. **The repository contradicted its own product intent.** Product guidance said rating-dependent training must be absent while design guidance explicitly retained an unrated reader. Consolidate lifecycle policy, link it from AGENTS.md, and add transition verification to deployment so future sets reuse the rules.

## Behaviors retained

The two set themes make the selected set recognisable. Literal tabs, colour jumps, readable local card images, in-place lightboxes, format-specific archetype notes, sources, and locally saved progress support real preparation. Hobbit's tier exercise and historical Draft decisions already have useful evidence and remain intact. The replay remains a reasoning exercise rather than a binary score.

## Limits and follow-up triggers

The Impeccable scan also flagged existing small functional text, padding and theme-token contrast candidates. The set-picker label was enlarged in this pass. The static contrast warning pairs the page's ink with its outer ground rather than the rendered paper panel; it is not proof of a rendered contrast failure. Remaining dense labels and padding merit a dedicated accessibility pass; no blanket WCAG compliance claim is made.

No physical-phone swipe test or assistive-technology user study is claimed. Existing dense Training controls and long archetype pages remain design choices to revisit with actual usage evidence. Full card browsing has colour jumps but no text search; add search if finding named cards becomes a frequent task, rather than expanding this lifecycle change. Dates alone do not schedule a data import. Review the manifest at the next published milestone and whenever new evidence is imported.
